# GuideAnts v1.1.0 – Draft Release Notes

**Long conversations that stay coherent** — explicit context compaction with recall, a live context meter, and per-conversation model override. Overflow now fails cleanly instead of silently unwinding. New Spark (DGX / GB10) backend image and llama.cpp v0.5.0 across all AI backends.

## What's new since v1.0.0

- **Context compaction with recall** (#156) – Compact a long notebook conversation at any turn boundary. A pure, deterministic engine extracts a five-section summary (Goal, Artifacts, Activity ledger, Unresolved errors, Directives) from everything before the boundary — no LLM call, no vendor knowledge. A `conversation_recall` tool, scoped to the requesting conversation, lets the model retrieve pre-boundary detail on demand, so compaction never loses anything permanently.
- **Context meter** (#156, local) – A meter in the composer footer shows how full the model's context window is, with color thresholds at 75 % / 90 %. For local llama models the window is read live from the running server's `meta.n_ctx` (the runtime value after memory-based auto-derivation); the token count is the provider-reported prompt size of the final round, not a character-count estimate. When the window is unknown the meter shows the real token count without a limit.
- **Context overflow fails cleanly** (#156) – The prior silent, destructive unwind-and-retry on overflow is removed. Overflow now propagates as a named, actionable error (`ChatContextOverflowException`) with no message content ever mutated. The UI names Compact as the remedy.
- **Per-conversation model override** (#157) – A model picker in the header toolbar lets you switch the model for a single conversation without touching global chat defaults. The override is request-scoped: it rides on the `sendMessageStream` payload as `modelDeploymentId` and leaves the catalog and settings untouched.
- **Spark (DGX / GB10) backend** (local) – New `guideants-ai:spark` image (`Dockerfile.cuda-spark`, linux/arm64) with the native engine set (llama.cpp / audio.cpp / stable-diffusion.cpp) plus supporting services. Ships with a dedicated compose file (`docker-compose.spark.yml`) and a launcher script (`installer/guideants-spark.sh`) that detects aarch64, checks the CUDA 13 driver, health-checks each service on its published port, and prints the port map. Build and push scripts updated to cover the spark variant.
- **llama.cpp v0.5.0** (#157) – All AI backend images (cpu, cuda, rocm, slim, vulkan) bumped from b10615 to the v0.5.0 release. The Dockerfiles now assert `libnccl2` presence (held by the new base image) instead of installing it.

## Improvements

- **No-audio-stream media handling** (#157) – Media files with no audio stream (e.g. a silent video, a screenshot with no track) are now detected via `ffprobe` before the ASR call. The job is marked `Skipped` and returns `Success` — no retry burn, no failed-job row. The failure classifier treats `NO_AUDIO_STREAM` and `UNREADABLE_MEDIA` as permanent.
- **Compaction boundary is applied on the first turn** (#156) – Fixed a defect where the first message after compacting silently sent the full uncompacted history. `ConversationUndoService` now clamps `CompactionBoundaryTurnIndex` to the highest surviving turn in the same `SaveChanges` when Undo deletes turns at or before the boundary, so a stale boundary can no longer exist.
- **Compaction summary points at recall** (#156) – The summary framing now explicitly states that detail was omitted and is retrievable via `conversation_recall`, so models call the tool instead of answering from the summary alone.
- **Compaction marker visible immediately** (#156) – The transcript boundary marker anchors after the boundary turn (not before the first turn after it), so it appears as soon as Compact succeeds, not on the next message.
- **Model catalog context-window metadata** (#156) – New `ContextWindowTokens` column on `Model` with a backfill from known cloud model windows at startup. The settings UI (Add Model wizard, catalog row edit) exposes the field. `knownCloudModels.json` seeded with initial values.

## What's under the hood

- **DB migrations** – `AddModelContextWindow` (context window on `Model`) and `AddCompactionBoundaryTurnIndex` (boundary on `NotebookConversation`).
- **Compaction engine** – `AntRunner.Chat.Compaction`: `CompactionEngine`, `MessageNormalizer`, `NoiseFilter`, `TurnFacts`, and per-section extractors (`GoalExtractor`, `ArtifactsExtractor`, `ActivityLedgerExtractor`, `UnresolvedErrorsExtractor`, `DirectivesExtractor`) plus `CompactionSummaryRenderer`. Pure and deterministic; no I/O, no DB, no LLM call.
- **Context window resolution** – `ContextWindowResolver`, `LearnedContextWindowCache`, `ModelContextWindowProbe` for cloud models; live `meta.n_ctx` from the llama.cpp server for local models.
- **Conversation recall** – `ConversationRecallService`, `ConversationRecallTools` (server-handled tool, structurally scoped via `InvocationContext`), `ConversationRecallServiceTests` (323 lines), wiring tests, exposure tests.
- **Streaming** – `StreamingEvent` gains a compaction-boundary marker event; `StreamingErrorEnvelope` carries the named overflow error.
- **Client** – `ContextMeter`, `CompactButton`, `conversationModelOverride` store, updated `reducer` / `useStreamingEventHandler` / `ConversationContext`, boundary marker in `CellList`, context-overflow message in `DraftUserCell`.
- **Validation** – Cross-domain compaction benchmark (`CompactionBenchmarkRunner` / `CompactionBenchmarkTests`), hermetic E2E test (overflow → compact → continue → recall), opt-in run against a real llama.cpp server, four ADRs in `docs/`.
- **GHCR images** – AI / support images republished to GHCR (`:main`, `:latest`, and `:v1.1.0`) for this cut: cpu, cuda13, rocm, slim, vulkan, **spark (new)**, plus PlantUML, MSSQL FTS, and SearXNG. Web API images (`guideants-webapi-ui-slim`, `guideants-webapi-ui-mssql`) published to GHCR `:main` from this commit.
- **Operator details** – `docs/release-runbook.md`, `docs/compaction-adr-*.md`, `docs/compaction-llamacpp-e2e-runbook.md`, `installer/README.md`.

## Notes

- Apple Silicon: prefer the **slim** AI backend (`linux/amd64` under emulation). DGX Spark / GB10 users: use the **spark** backend.
- The compaction boundary is per-conversation and monotonic. Compacting again moves the boundary forward; it never moves back.
- `conversation_recall` is only exposed to the model when a compaction boundary exists on the conversation.
