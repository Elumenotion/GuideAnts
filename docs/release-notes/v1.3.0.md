# GuideAnts v1.3.0 – Draft Release Notes

**llama.cpp v1.0.0 across all AI backends (CUDA hosts need updated drivers), configuration surfaces that work while local engines are down, and a per-conversation thinking-level toggle in the chat composer** — the script execution agent is rebuilt on auth schemes and bounded identities, and Electron moves to 45 with a batch of dependency updates.

> ⚠️ **CUDA hosts: updated drivers required.** The llama.cpp bump below moves the CUDA images onto CUDA 13.5; the `guideants-ai-cuda13` image will not start on a host whose GPU drivers predate it. Update the host's NVIDIA drivers before the first pull of this release's AI images.

## What's new since v1.2.0

- **llama.cpp v1.0.0 in all AI images** (366a3518) – All six backend Dockerfiles (cpu, cuda13, rocm, slim, vulkan, spark) move from the v0.7.0 base (`server-*-b11669`) to `server-*-b12407`, the newest published server build (v1.0.0 is upstream build `b12359`). **Starting the CUDA 13 image requires updated drivers on the host (CUDA 13.5)** – see the note above. The bump also lands two llama-admin-service fixes: the router soft-reload now sends `GET /models?reload=1` (a bare `?reload` is a silent no-op in the engine and left new presets invisible until a full container restart), and the legacy onboarding download path registers its fresh alias with a non-destructive soft reload instead of SIGTERM-hard-reloading the router. Router alias deletion now triggers a soft reload so a removed alias disappears from the running router immediately.
- **Configuration surfaces work while engines are offline** (#185) – Settings pages and the notebook header toolbar no longer wait minutes on a dead engine: reachability now lives in its own plane. A background loop probes the configured endpoint universe every 15 s at the socket level (a 503 from an up-but-idle engine is *reachable*), writes a single-flight availability cache plus a last-known inventory mirror, and no configuration request makes an inline network call. Offline states become named (`ENDPOINT_UNREACHABLE`, `RUNTIME_ARTIFACT_MISSING`) so the local-model editors stay usable with the engine down – a deleted artifact shows a "removed artifact" line offering Remove, pointedly not re-download, which cannot work against an unreachable engine. The API now also records what it installed itself: a new `ServiceLocalModelInstallations` table (download coordinates, artifacts, target directory) means deleting a local model is a configuration act that returns 200 with `diskCleanup` true/false, and the API can tell a dead engine from a deleted model.
- **Thinking-level toggle in the chat composer** (#180, #182, #183) – `Ctrl+` opens a quick change to the thinking level for the current conversation (server-backed per-conversation reasoning-effort override on `sendMessageStream`). It is intentionally conversation-scoped and not persisted when you navigate away. Follow-ups keep the level chip visible when a level is set (#182, #183).
- **Script execution agent rebuilt on layered modules and auth schemes** (#181) – The agent's ~3,500-line `Program.cs` becomes a 63-line `Main` over `Authentication` / `Endpoints` / `Runtime` / `Scope` / `Models` modules; per-endpoint token guards become ASP.NET authentication schemes with authorization policies (same headers, same responses – and `/health` probes no longer log spurious "agent token missing" warnings). Notebook execution identities grow to 24-hex names (~2^96 collision space) with in-place uid/gid-preserving migration of legacy 12-hex identities, an LRU bound of 512 live identities (`SCRIPT_EXECUTION_MAX_NOTEBOOK_IDENTITIES`), and an opt-in startup reaper for orphan identities (`SCRIPT_EXECUTION_REAP_ORPHAN_IDENTITIES`, default off). Text request bodies get streaming per-route caps (install-scripts 16 MB, apply 64 KB, requirements 100 KB, apt-packages 64 KB) mapping to plain-text 413.
- **Electron 45 and dependency updates** (#184) – Client moves to `electron 45.3.0` / `electron-builder 26.18.0` with a batch of flagged-package updates (`dompurify 3.4.17`, `fast-uri 3.1.9`, `qs 6.16.2`, `undici 6.29.1` / `7.30.2`, pinned `katex 0.19.1`), and the guide-builder crew UI is fixed for a Tailwind behavior change in this version.

## Improvements

- **Stale turns are recovered while the API is running** (#186) – `ConversationTurnRecoveryService` is registered as a hosted service that sweeps the database every second, terminalizing `streaming` turns past its 3-minute cutoff, honoring `cancel_requested` markers, and pruning incomplete tool calls, in capped `LastUpdated`-ordered batches of 20. (The service was previously only reachable from explicit test calls; it now runs in the live host.)
- **Integration-test host hardening** (#186) – Test hosts no longer arm config-file watchers (the runner had exhausted its 128-instance inotify limit, failing 86 of 271 tests in their initialize method), and the integration suite stops running the recovery service as an unsupervised actor so one test's live sweep cannot claim another's in-flight turns; explicit recovery coverage stays in `ConversationTurnRecoverySqlIntegrationTests`.

## What's under the hood

- **DB migration** – `AddServiceLocalModelInstallations` (new table only, `Down` is a single `DROP TABLE`); the existing startup migration applies it, no manual SQL step.
- **Reachability plane** – `Services/Reachability/` (probe, 15 s loop, single-flight endpoint cache, inventory mirror, snapshots) and `RoutingProbeMode { Live, NonBlocking }` in `RoutingReadinessService`: `Live` keeps today's byte-for-byte behavior on dispatch preflight, explicit load/unload, and chat-readiness; `NonBlocking` fills runtime fields from the cache. Four architecture contract tests fail the build if a configuration surface stops naming its probe mode, the toolbar regains an HTTP dependency, a readiness read writes a `ServiceModes` selection, or a deferred disk-delete reappears. Twelve new MSTest files cover the cache, loop, mirror, non-blocking readiness, install store, offline preflight, and settings concurrency; eight new vitest cases cover the offline Overview tab and the chat / TTS / ASR / Image panels.
- **Script execution agent** – `ScriptTokenAuthenticationHandler` / `AdminTokenAuthenticationHandler` schemes, `AgentAuthorizationPolicies`, `NotebookExecutionIdentityProvider` (24-hex names, LRU eviction, optional orphan reaper), per-route streaming body caps in `Models/AgentRequestBody.cs`, `StartupFilesystemHardening` now self-locates from `AppContext.BaseDirectory`, and the pure-move reorg into `Authentication/`, `Endpoints/`, `Runtime/`, `Scope/`, `PathGuard/`, `Logging/`, `Models/` (namespaces unchanged).
- **llama-admin-service** – pid-file / last-exit tracking for `llama-server` (30 s restart timeout matching the chat UI spinner), `?reload=1` soft-reload correction, soft reload on the onboarding download path, reload callback on alias removal.
- **Client** – `DraftUserCell` thinking-level popover, `conversationReasoningEffortOverride` store, `PresenceLine` / `RemovedArtifactNotice` toolbar components, offline `OverviewTab`, `routerPreset.ts` preset updates for the llama.cpp bump.
- **Operator details** – `docs/release-runbook.md`, `docs/local-ai-lifecycle/DECISIONS.md`, `docs/settings-architecture.md`, `docs/notebook-header-service-toolbar-spec.md`, and other doc updates.

## Notes

- **Driver requirement (action needed on CUDA hosts)** – The `cuda13` image runs on CUDA 13.5; hosts with older NVIDIA drivers will fail to start the container. Update drivers before installing, or pick another backend.
- **llama.cpp base tag is `b12407`** – If you reference the base image manually, use `ghcr.io/ggml-org/llama.cpp:server-*-b12407` (upstream publishes under build tags; `v1.0.0` corresponds to `b12359`, the Dockerfiles take the newest published server build).
- **GHCR images (pending per runbook)** – AI / support images (cpu, cuda13, rocm, slim, vulkan, spark, PlantUML, MSSQL FTS, SearXNG) must be published to GHCR with `:v1.3.0`, `:main`, `:latest`, and their immutable build tags **before** the GitHub Release is published; web API images (`guideants-webapi-ui-slim`, `guideants-webapi-ui-mssql`) publish via their CI workflows. Release zips pin the `:v1.3.0` tags.
- **Migration** – `AddServiceLocalModelInstallations` applies automatically at startup; existing volumes and data are unaffected.
