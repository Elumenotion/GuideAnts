# GuideAnts v1.4.0

**The entire .NET stack moves from 8 to 10 (all 22 server projects, all seven AI image variants, the web API images, and the PlantUML sandbox), and guide export stops loading every assistant's file binaries in one query** — the fix for the 2026-11-23 export hang where a multi-file guide's export died in materialization.

## What's new since v1.3.0

- **.NET 8 → .NET 10 across the server stack** (72f86719) – All 22 .NET projects retarget `net10.0`. The web API image moves from `mcr.microsoft.com/dotnet/sdk:8.0` / `aspnet:8.0` to the `10.0` bases; the AI images (cpu, cuda13, cuda-spark, rocm, slim, vulkan) and the PlantUML sandbox install the ASP.NET Core 10.0 runtime via the portable `dotnet-install.sh` channel instead of the MS apt feed (there is no `aspnetcore-runtime-10.0` package for Ubuntu 22.04 — including the MSSQL-FTS web API variant, whose runtime stage installs the portable runtime and no longer pins `aspnetcore-runtime-8.0`). The API surface change in `Program.cs` (`ForwardedHeadersOptions.KnownNetworks` → `KnownIPNetworks`) is the one non-mechanical code change the bump required.
- **Guide export no longer joins assistant files** (#188) – Exporting a guide with files (especially a crew with several assistants, each carrying `varbinary(max)` content) timed out because the guide graph was loaded with `Include(a => a.Files)` plus the crew `ThenInclude(a => a.Files)` — under the app-wide single-query splitting that is one statement whose rows multiply across every collection include, each row carrying every file's `ContentBytes`, and the export died in materialization. File binaries are now fetched by a dedicated per-assistant query (`AssistantFiles` filtered by `AssistantId`, ordered by `RelativePath`), loaded exactly once each and never part of the guide's Include tree. A SQL-translation regression test (`ExportGuideAsync_query_does_not_join_assistant_files`) fails the build if `AssistantFiles` or `ContentBytes` ever reappears in the export graph query.

## What's under the hood

- **Bump-driven code fixes** – The streaming read loops in the four chat clients that read SSE (Google Gemini, Hugging Face, OpenAI-compatible, OpenRouter) and the integration-test stream helpers switch from `while (!reader.EndOfStream)` + `ReadLineAsync()` to the .NET 10 `while (await reader.ReadLineAsync() is { } line)` form (`EndOfStream` no longer throws on a `TextReader`). `RebuildEmbeddingsHandler` takes explicit `List<T>` initializers for its status/type filters.
- **Package updates riding the retarget** – `Microsoft.Data.SqlClient` 6.1.3 → 6.1.8 (SNI runtime 6.0.2 → 6.0.3), `Microsoft.Identity.Client` 4.79.2 → 4.84.2, `Microsoft.AspNetCore.Mvc.Testing` → 10.0.15 in both test projects, `Microsoft.Extensions.{Dependency,Logging}.Abstractions` 9.0.11 → 9.0.21, and the pinned `System.Text.Json` references are dropped (the framework provides it on net10). EF Core stays on 9.0.11.
- **AI images** – The Python-dep builder stages gain `CFLAGS=-Wno-error=incompatible-pointer-types` (newer GCC treats that warning class as an error and broke the wheel builds).

## Notes

- **Breaking change for self-builders** – Anything that builds the server outside the shipped images (local `dotnet run`, custom compose) needs the .NET 10 SDK installed; the released images are self-contained.
- **CUDA hosts: unchanged driver requirement from v1.3.0** – The `cuda13` image still runs CUDA 13.5 and will not start on hosts with older NVIDIA drivers.
- **GHCR images (pending per runbook)** – All pinned packages (webapi-ui-slim, webapi-ui-mssql, ai cpu/cuda13/rocm/slim/vulkan/spark, PlantUML, MSSQL FTS, SearXNG) must be rebuilt and published to GHCR with `:v1.4.0`, `:main`, `:latest`, and their immutable build tags **before** the GitHub Release is published; release zips pin the release tags.
- **No DB migration** – This release contains no schema changes; existing volumes and data are unaffected.
