# Native AI Migration — Locked Decisions (single source of truth)

Last updated: 2026-07-02
Status: D1 **LOCKED** — TTS migrates to **Chatterbox** (`ResembleAI/chatterbox` via
audio.cpp), confirmed by product call 2026-07-02. This unblocks Phase 3 and, because
`chatterbox` is native C++ (no torch), satisfies **D8**'s dependency for the torch-removal
goal (completion still requires Phase 3 to ship). D2–D7 LOCKED at recommended values
(confirm before the phase/gate they gate). D7 governs the torch-removal gate's Tier B
(sandbox torch); D8 records that torch removal depends on D1/TTS (now resolved).

This file freezes the design decisions for the migration planned in
[`00-overview.md`](./00-overview.md). It resolves the open questions in `00-overview.md`
§6 as `D1`–`D6` and records the frozen invariants every phase must uphold.

Rules:

- If a decision below is `UNDECIDED`, any phase listed under "Blocks" is blocked.
- Changing a locked decision after a phase ships requires reverting and re-dispatching the
  impacted phase (see [`STATUS.md`](./STATUS.md) deviation log).
- Phase docs are the design context; **this file is the contract**. A phase built against a
  different value than the one locked here is an automatic gate FAIL.

## Part B — Frozen invariants (not open for reinterpretation)

From `00-overview.md` §1–§3 and the user's standing rules:

- **Public route compatibility is absolute.** The nginx prefixes `/asr/`, `/tts/`, `/emb/`,
  `/sd/`, `/llama-cpp/`, `/llama-admin/`, `/sandbox/`, `/media/` are preserved across every
  phase. Internal ports may move; public prefixes and their request/response shapes may not
  (enforced by [`contract-preservation-gate.md`](./contract-preservation-gate.md)).
- **No .NET / client contract changes** except where a phase doc or **D11** explicitly
  lists one. Planned exceptions: Phase 3 voice-preset list (`ServiceEditorMetadataProvider.cs`,
  after D1); **D11** reconcile behavior in `LocalAiStartupWarmupService.cs` and routing-save
  triggers (admin HTTP contracts unchanged).
- **Routing-aware idle is mandatory (D11).** A service whose default `ServiceModes` row
  routes to a non-local provider must not retain a loaded model. Idle = unload + poll until
  unloaded.
- **One reconciliation orchestrator (D11).** The API owns desired runtime state; container
  `GA_*_AUTO_LOAD_ON_STARTUP` must not compete (retired by Phase 4).
- **LLM-first load order is frozen (D11).** Aux unload reverse → llama → aux load forward;
  only services in the Warm desired state are loaded.
- **Global routing governs local engine state (D11).** Notebook scope cannot override global
  routing to warm a local engine.
- **The consumer-invisible embedding width is `1536`** (SQL `vector(1536)`,
  `DocumentChunk.cs:51-53`; search `HybridSearcher.cs:57,82,87`), reached by
  `EmbeddingVectorDimensions.NormalizeToTarget` (`Target = 1536`) for **every** provider
  (`ProviderRoutedEmbeddingService.cs:69`). This is the real invariant — **not** 1024. Today
  the local provider expects its model's native **1024** (`LocalEmbeddingService.cs:98-102`,
  the const `SourceVectorDimensions = 1024` at `:15`), then normalizes 1024→1536 (`:114`).
  `NormalizeToTarget` **zero-pads < 1536 and silently truncates > 1536** — a latent
  silent-normalization. **D9 makes the ceiling explicit at model-selection time:** the
  embeddings picker offers **only** `producedDimension <= 1536` GGUF entries, the download
  handler asserts the actual produced dim equals the declared `producedDimension` after load
  and rejects `> 1536` **loudly** (never truncates), and on a model change
  `SourceVectorDimensions` is updated as a matched pair + the corpus is re-embedded (D3). The
  `/emb/embed` route shape and the normalized 1536-wide vector remain invisible to clients.
- **No runtime fallbacks (user rule).** Rollback is "redeploy the previous image tag,"
  never "silently fall back to the torch path inside the same image." Hidden fallback logic
  is a defect. Where a backend/op is unsupported (e.g. Vulkan op coverage), the phase
  *decides* (fix upstream, or ship that flavor CPU-backed **explicitly documented**) — it
  does not degrade silently.
- **Data plane native, control plane consolidated.** Inference engines are persistent
  native processes (llama-server instances, `audiocpp_server`, `sd-server`); admin/
  lifecycle/download logic converges into one service. Inference requests never transit the
  control plane.
- **Persistent processes only.** Per-request CLI invocation (`audiocpp_cli` has no daemon
  mode) is not viable; every AI engine is a long-lived process.
- **`ga-admin` ≠ `ScriptExecutionAgent`.** (D6 security invariant, restated because it is
  load-bearing.) The consolidated control plane is never folded into the sandbox process.
- **`Dockerfile.slim` is untouched.** It runs only sandbox + media + nginx and none of the
  affected services.
- **SD inference path unchanged.** `sd_service.py`'s admin/facade role is absorbed in
  Phase 4, but the native `sd-server` and the `/sd/txt2img` / `/sd/img2img` contracts are
  not redesigned.
- **One shared `/opt/venv`; sandbox torch removal is D7 (FLIPPED 2026-07-02).** There is no
  distinct "service venv" vs "sandbox venv" — `guideants-ai` runs both the AI services and
  the ScriptExecutionAgent sandbox out of the same `/opt/venv` (verified:
  `Dockerfile.cuda:150-170`, `build_guideants_ai.sh`, `script-agent-admin/reconcile.sh:146`).
  Tier A (torch-*dependent service packages*) is removed as ASR + TTS + embeddings migrate
  (invisible to sandbox users). **Tier B (torch itself) is now also executed** per the D7
  flip — this **does** affect sandbox scripts: any user script that `import torch` now fails
  loudly (no shim, no silent degrade), an explicitly accepted consequence, not a silent one.
